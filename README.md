# dsimaging-store

Storage service and controller for source imaging data used by dsImaging.

The store contains only source images, operator-provided masks, metadata,
manifests and content-hash indexes. Derived artefacts generated by analysis jobs
are written by dsHPC into its artifact/publish directories, not into this store.

## Local MinIO

Use `dsimaging-admin` for lifecycle management:

```bash
dsimaging-admin --backend minio store up
dsimaging-admin --backend minio store init
dsimaging-admin --backend minio store doctor
```

`store up` runs this repository's `docker-compose.yml`. `store init` creates the
bucket, enables versioning and configures MinIO bucket events for the
controller webhook. There is no separate init container.

The repository can still be run directly:

```bash
docker compose up -d
dsimaging-admin --backend minio store init
```

## AWS S3

For AWS, `dsimaging-admin store init` provisions the bucket, enables versioning
and encryption, creates an SQS queue and wires bucket notifications to it:

```bash
dsimaging-admin --backend aws \
  --region eu-west-1 \
  --bucket my-imaging \
  store init
```

Deploy the controller wherever appropriate and set:

```bash
DSIMAGING_SQS_QUEUE_URL=<queue-url>
DSIMAGING_AWS_REGION=eu-west-1
BUCKET_NAME=my-imaging
```

When `DSIMAGING_SQS_QUEUE_URL` is present, the controller starts an SQS
long-poll worker. The MinIO webhook endpoint remains available but is unused
unless a deployment wires events to it.

## Services

| Service | Purpose | Port |
|---|---|---|
| `minio` | Local S3-compatible object storage | 9000 API, 9001 console |
| `controller` | Webhook receiver, SQS worker and index reconciler | 8080 |

## Controller API

- `GET /healthz` and `GET /health`
- `GET /datasets`
- `POST /reconcile/<dataset-id>`
- `POST /webhook/minio`

`POST /reconcile/<dataset-id>` is available in all deployments as a manual
pull-based safety net.

## Reconcile behaviour

The controller reacts to object-created and object-removed events under:

- `datasets/<dataset_id>/source/images/`
- `datasets/<dataset_id>/source/masks/`

It rebuilds:

- `indexes/content_hash_index.parquet`
- `indexes/masks_content_hash_index.parquet` when masks exist
- `metadata/sample_manifests.parquet`
- `metadata/samples.parquet`
- `manifest.yaml`

`dsimaging-admin dataset publish` writes a `.publish-lock` while uploading. The
controller defers reconcile while that lock exists.

## Configuration

| Variable | Default | Description |
|---|---|---|
| `MINIO_ROOT_USER` | `minioadmin` | Local MinIO access key |
| `MINIO_ROOT_PASSWORD` | `minioadmin123` | Local MinIO secret key |
| `MINIO_PORT` | `9000` | MinIO API port |
| `MINIO_CONSOLE_PORT` | `9001` | MinIO console port |
| `CONTROLLER_PORT` | `8080` | Controller port |
| `BUCKET_NAME` | `imaging-data` | Dataset bucket |
| `DSIMAGING_S3_ENDPOINT` | unset | S3 endpoint override |
| `DSIMAGING_ACCESS_KEY` | unset | Static S3 access key |
| `DSIMAGING_SECRET_KEY` | unset | Static S3 secret key |
| `DSIMAGING_SQS_QUEUE_URL` | unset | Enables AWS SQS worker |
| `DSIMAGING_AWS_REGION` | `us-east-1` | AWS region |
| `RECONCILE_INTERVAL_SECONDS` | `10` | Dirty dataset reconcile loop delay |
